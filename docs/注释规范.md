# 注释规范（黑格尔哲学引擎 · 原文注释版）

> 本文件汇总本项目注释的全部约定（2026-08-26 归纳）。新写章节、新作品、讨论补充、二手文献整合一律照此执行。
> 关联：`docs/讨论分段索引.md`（定位与整合工作流）、`docs/义解_环节对应表.md`（二手文献锚点）、`docs/运行简报.md`（质量与待办）。

## 一、目标与定位

- 以**德语原文**（zeno.org 1807 年版）为底，引擎框架读书笔记在侧；引文锚点回原文，自动对拍校验。
- 阅读单位是**段落**（编号 章.段，如 1.7），不是原书页码——页面已贴出原文，**page 概念在显示层废弃**（原书页码保留在数据层与悬停提示，供对拍与引用核对）。
- **希腊哲学项目（柏拉图等）原文选择原则**（2026-08-27 用户裁定）：尽量用**德文译本**为底（Zeno 版）——古希腊语与德语在哲学概念层亲缘紧密（Sein/ousia、Wesen/eidos、Begriff/logos、Grund/archē：德语哲学概念本为翻译希腊哲学而锻造，从沃尔夫经康德到黑格尔的积淀）；德国希腊学传统把希腊哲学**当作哲学**来译，保留概念推演的可读性；且与引擎框架（黑格尔体系）术语系统天然衔接（如巴门尼德篇的 Eins/Sein 正是小逻辑 §84 起跑处的词）。**引文一律逐字取自德译本**（17/17 对拍），中文只在笔记解释层；斯蒂芬奴斯页码作锚。

## 二、术语纪律（红线）

1. 禁「知—行」框架（已停用，作废的原始数据）。
2. 禁「正反合 / 正题 / 反题 / 合题」（康德式术语）。
3. **dialektisch = 解构的力；spekulativ = 思辨的（在思维中推演）**——功能分工，不是先后步骤。
4. 引擎正式名称：**die absolute Negativität**。
5. 引德文须逐字取自原文并标注（段落/页码），不凭记忆。

## 三、引擎框架规范

- 每形态按 **概念—判断—推论** 三段循环展开；做功方式随介质：存在论=过渡、本质论=反思、概念论=发展。
- **诊断（diagnose）从形态内部的三段结构推出**（如：观察把判断压成登记、实践把判断当作否定行动、个体性把判断伪装成办事情），不贴外部标签。
- 负面形态——**坏的无限性、片面的否定性**——是绝对否定性扬弃自身的**尚待消解环节**，出现处加 ⚙️ 引擎标注，说明其如何推动整体前进。
- 关键概念（如 Bildung 双向塑造）加 🔑 关键概念标注。
- 引擎描述工作（V1 措辞精确化、「尚待消解环节」系统化）留待小逻辑项目后。

## 四、UI 规范（双栏布局）

### 原著侧（左栏）
- **纯德文**，不混入任何中文（阅读辅助、术语条都在笔记侧）；这是硬性视觉原则。
- 段落编号 章.段（如 `1.7`），无页码徽章（原书页码只进数据层/悬停提示）。
- 段落卡片：浅色底、圆角、细边框；被引片段用 `mark.cited` 高亮（下划线 + 淡色底）。
- 未引段：正文下方不显示任何内容（其翻译卡在右栏对应行）。

### 笔记侧（右栏）
- 笔记卡片 `position:sticky; top:1rem` **吸顶跟随**——长段落滚动时引文与注释始终可见；段落读完才释放。
- 卡片内顺序固定：**标题行 → 引文（qwrap，斜体灰）→ 原解读 → 本节术语条 → 链路图 → 讨论补充**。
- 标题行：`小节 章.节 + 环节名 + 〔段 N〕引文链接 + （段落 N）`。
- 本节术语条（gterms）：小字 chips，`德文词 中文`；首次出现标 §（琥珀色）；上限 10。
- 链路图（diagram）：双节点 CSS grid（左节点 ⇄ 右节点 + 底部结论条）；窄屏纵向堆叠。
- 讨论补充（sup）：默认展开（`<details open>`）；三种徽章——⚙️ 引擎·die absolute Negativität（强调色）、🔑 关键概念（琥珀色）、普通（无徽章）。
- 示例类补充口语化（见第五节）。

### 引文注释规范
- 每环节**一条德文引文**作为锚（引文对拍 162/162，逐字命中原文）。
- 引文链接标签 **〔段 N〕**，点击跳回原文段落（`#c1-p7`）；原书页码在 `title` 悬停提示。
- 未命中引文标红（`.miss`），提示「？未命中」——禁止带病发布。
- 原文段中的被引片段高亮（`mark.cited`），悬停可定位来源。

### 导引阅读（未引段阅读辅助）规范
- **只在未被引用的原文段**显示；被引段已有术语条，不重复。
- 翻译卡（`.rh-note`）在**笔记侧**，与对应段落并排（`.pair`），sticky 跟随；原文列保持纯德文。
- 内容：**首句 + 末句翻译**、长句拆分、难句翻译；**长句按德语语序硬译**（不改变语序，`de|zh` 逐块对齐）；障碍词 3-5 个（古旧拼写、低频实词、易读断结构词，非术语）。
- 标签：首句 / 难句（中段）/ 末句 / 障碍词。
- 数据在 `notes_pheno/reading_help.json`；翻译为人工定稿（不机翻）。

### 移动端（≤1000px）
- 单栏堆叠：`.block`/`.pair` 降为 1 列，笔记与翻译卡堆在段落下方；目录变抽屉（汉堡按钮）。
- sticky 关闭（吸顶会遮内容）；触控目标 ≥44px 与断行优化（≤520px 档）待实施。


## 五、笔记内容规范

- 原解读（explain）：引擎措辞、加粗关键词、德文术语带括号、术语红线。
- 讨论补充（supplements）：每环节第 5 元素 `[{date, title, content}]`，**追加不覆盖**，默认展开。
- **示例类补充口语化**：去文本腔、口头化（如「恐怖的极致不是死得惨，而是死得没意义」）；保留德文锚点、来源标注、引擎核心术语；除核心链路图与引擎术语外尽量减少学者腔调。

## 六、术语条规范

- 术语表：**哲学家主表** `viewpoints/glossary/<哲学家>.json`，每术语 {term, zh(canonical), works[]}，跨作品译法统一（规范性）。
- 选词双重过滤：①术语表内 ②该段德文引文出现；上限 10；首次出现标 **§**。
- **选词四条标准**（2026-08-26 用户裁定）：①黑格尔重要概念，特别是与引擎相关的（概念/判断/推论、否定性、扬弃、无限性等）；②在逻辑推演的重要描述中采用的（矛盾、分裂、反思、过渡、发展、根据、条件、规定等）；③考虑德语特点——词形变化（Sein/Seiende）与形容词名词化（das Lebendige、das Allgemeine、das Andere 等）；④与西方历史文化强相关的词（思想流派：斯多亚/怀疑主义/启蒙；神话与事件：安提戈涅、俄狄浦斯、斯芬克斯、宗教改革等）。
- 译法口径与笔记正文一致：从行内注释自动抽取 + 人工修正层（MANUAL_FIX），不新造翻译。
- `validate_glossary.py` 查跨作品冲突；改译法改 MANUAL_FIX（可复现）。
- **页面底部通栏术语表**：完整主表两列（column-count:2）通栏展示，不区分原文/笔记侧，按字母排序。

## 七、阅读辅助规范（未引段）

- **只在未被引用的原文段**显示（被引段已有术语条）。
- 内容：**首句 + 末句翻译**、长句拆分、难句翻译；**长句按德语语序硬译**（不改变语序，逐块 de/zh 对齐）；障碍词 3-5 个（非术语的阅读障碍词：古旧拼写、低频实词、易读断结构词）。
- 位置：翻译卡在**笔记侧**（右栏），与对应段落并排（.pair），sticky 跟随；原文列保持纯德文。
- 数据：`notes_pheno/reading_help.json`（paragraphs{id: {first/middle/last:[{de,zh}], words:[{de,zh}]}}）。

## 八、二手文献三纪律（庄振华案例定型）

1. **不采用其译文**：宁可不翻译，引文一律用德文原文或我们自己的话转述。
2. **删去其对其他哲学家的论战**（哈贝马斯/霍耐特/科耶夫/马克思/波普尔/尼采/青年黑格尔派等）：只留文本义理；**文本内**的批判（如黑格尔批康德）保留。
3. **事实类大胆采纳、分析类过引擎**：西方历史/思想史事实可大胆采用（我们的短板）；义解分析必须与引擎框架同向才用，不符的改写或不用。

## 九、防串文机制

- 笔记内容须可追溯到 文献观点库 T-# 或 基础观点库 V-#，或标注来源（如庄振华《义解》出处）。
- A 文献观点不得移植 B 文献；跨文本成立的观点先提升为 V# 再引用。

## 十、验证链（每次重建必须全过）

- 引文对拍（norm 归一 + 大小写不敏感子串匹配）
- 标签配平（`verify_ch123.py`）
- 段落计数 729、引文链接数、章节数
- 观点库校验（base/lit 双向一致）
- 术语主表校验（`validate_glossary.py`）

## 十一、数据格式速览

- `notes_pheno/ch{n}.json`：title / pages / mode / gestalten[{name, position, bestimmung, bewegung[[label, page, quote, explain, supps?, diagram?, paras?]], diagnose, uebergang, supps?}]
- `notes_pheno/reading_help.json`：未引段阅读辅助
- `viewpoints/glossary/黑格尔.json`：哲学家术语主表
- `viewpoints/base.json`、`viewpoints/lit.json`：观点库（V# / T#）

## 十二、工作流

1. 抓章原文（zeno）→ 提取（页码锚点入数据）→ 提目录（`docs/黑格尔哲学引擎_大纲.md`）
2. 写环节笔记（引擎框架）→ 引文锚点 → 逐条对拍校验
3. 讨论 → 按 `docs/讨论分段索引.md` 定位 → 整理（引擎措辞）→ 整合（supplements）→ 重建验证
4. 二手文献：三纪律 → 锚点核对（`docs/义解_环节对应表.md`）→ 事实类/分析类分流 → 插入 → 重建验证
5. 每轮结束：更新 `docs/运行简报.md`（质量指标 + 反推结论 + 下一轮待办）
